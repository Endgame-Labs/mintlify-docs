Connect Snowflake so Endgame can use data from the tables, views, and dynamic tables you choose. Endgame syncs them every hour and includes what it finds in Endgame chats.

## Before you start

- You need to be an Endgame admin.
- In Snowflake, you need to be an ACCOUNTADMIN or have equivalent permissions.
- You need OpenSSL installed on your computer to create a key pair.
- To connect, you'll need an **account identifier**, a **username**, a **warehouse**, and the user's **private key**. The steps below walk you through creating each one.

## Set up Snowflake for Endgame

<Steps>
  <Step title="Generate a key pair">
    Endgame uses [key-pair authentication](https://docs.snowflake.com/en/user-guide/key-pair-auth) to connect to your Snowflake account. Generate a key pair by running these commands in your terminal:

    ```text
    # Generate a private key (PKCS8 format, unencrypted)
    openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out snowflake_key.p8 -nocrypt
    
    # Extract the public key
    openssl rsa -in snowflake_key.p8 -pubout -out snowflake_key.pub
    ```

    This creates two files:

    - `snowflake_key.p8` — your private key, which you'll give to Endgame.
    - `snowflake_key.pub` — your public key, which you'll register in Snowflake.

    Keep your private key secure. Don't share it or commit it to version control.
  </Step>
  <Step title="Create a role and service user in Snowflake">
    Open a SQL worksheet in Snowflake (click **+ Create** > **SQL File**) and run the following commands.

    1. Create a read-only role:

    ```text
    CREATE ROLE ENDGAME_CONNECTOR_READONLY;
    ```

    This creates a new role with no permissions. You'll grant specific permissions in the next steps.

    2. Grant warehouse access:

    ```text
    GRANT USAGE ON WAREHOUSE <your_warehouse> TO ROLE ENDGAME_CONNECTOR_READONLY;
    ```

    Replace `<your_warehouse>` with your warehouse name (for example, COMPUTE\_WH). This lets the role run queries.

    3. Grant database access. For each database you want Endgame to access, grant the appropriate permissions:

    **For standard databases:**

    ```text
    GRANT USAGE ON DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    GRANT USAGE ON ALL SCHEMAS IN DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    GRANT SELECT ON ALL TABLES IN DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    GRANT SELECT ON ALL VIEWS IN DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    
    -- For future objects (so new tables are automatically accessible)
    GRANT USAGE ON FUTURE SCHEMAS IN DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    GRANT SELECT ON FUTURE TABLES IN DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    GRANT SELECT ON FUTURE VIEWS IN DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    ```

    **For shared or imported databases:**

    ```text
    GRANT IMPORTED PRIVILEGES ON DATABASE <database_name> TO ROLE ENDGAME_CONNECTOR_READONLY;
    ```

    4. Create the service user.

    First, get your public key content. Open `snowflake_key.pub` and copy the content between the header and footer lines (leave out `-----BEGIN PUBLIC KEY-----` and `-----END PUBLIC KEY-----`). Remove any line breaks so it's a single continuous string.

    Then create the user:

    ```text
    CREATE USER ENDGAME_SERVICE_USER
    TYPE = SERVICE
    RSA_PUBLIC_KEY = '<your_public_key_content>';
    ```

    5. Assign the role to the service user:

    ```text
    GRANT ROLE ENDGAME_CONNECTOR_READONLY TO USER ENDGAME_SERVICE_USER;
    
    ALTER USER ENDGAME_SERVICE_USER SET DEFAULT_WAREHOUSE = <your_warehouse>;
    ALTER USER ENDGAME_SERVICE_USER SET DEFAULT_ROLE = ENDGAME_CONNECTOR_READONLY;
    ```
  </Step>
  <Step title="Find your account identifier">
    Your Snowflake account identifier is the part before `.snowflakecomputing.com` in your Snowflake URL, and it's also shown in the account selector. It usually looks like `orgname-accountname` (for example, `myorg-account123`).

    You can also find it by running:

    ```text
    SELECT CURRENT_ORGANIZATION_NAME() || '-' || CURRENT_ACCOUNT_NAME();
    ```

    For more details, see [Snowflake account identifiers](https://docs.snowflake.com/en/user-guide/admin-account-identifier).
  </Step>
</Steps>

## Connect Snowflake

1. In [**Settings** > **Organization** > **Integrations**](https://app.endgame.io/settings/integrations), find Snowflake and click **Connect**. You can search for "Snowflake", or choose **Available** to show only integrations you haven't connected yet.
2. Enter your **Account identifier**, the **Username** of the service user (for example, `ENDGAME_SERVICE_USER`), the contents of `snowflake_key.p8` as the **Private key (PEM)**, and your **Warehouse**.
3. Click **Connect**.

Endgame opens the Snowflake page so you can choose what to sync.

## Choose objects to sync

1. On the Snowflake page, go to **Data sync**.
2. In **Object identifier**, enter the fully qualified name of a table, view, or dynamic table, as `DATABASE.SCHEMA.OBJECT_NAME`.
3. Click **Add object**.

Endgame checks that the object exists and that it can access it, then adds it to **Synced objects**. The list shows each object's size status, row count, and when it last synced.

<Danger>
  Tables with 100,000 or more rows, or over about 200 MB, won't sync. Tables over 50,000 rows or 100 MB get a size warning. Use summarized Snowflake views, not raw event data. **For best performance, keep tables under 20k rows.**
</Danger>

<Frame caption="Data sync is where you add the Snowflake objects Endgame syncs.">
  <img

To stop syncing an object, click the trash icon next to it in **Synced objects**, then click **Remove**. Endgame stops syncing that object.

<Info>
  Snowflake tables usually describe your whole organization, so Endgame treats
  them as organization-wide data rather than tying them to one account.
</Info>

## Update credentials or disconnect

Use the **Connection** section at the bottom of the Snowflake page. See [Manage a connected integration](/integrations/overview#manage-a-connected-integration).

- **Update credentials** opens the same dialog as connecting, with nothing prefilled. Use it when you rotate the service user's key.
- **Disconnect** stops syncing data from Snowflake.
